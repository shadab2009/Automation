# SHADAB AI PERSONAL ASSISTANT

A secure, provider-agnostic personal messaging assistant with a simulator, responsive dashboard, PostgreSQL/Prisma persistence, session authentication, and an extensible AI boundary.

## Quick start

Requirements: Node.js 20+, npm 10+, and Docker Desktop (recommended).

```bash
cp .env.example .env
npm install
npm run db:up
npm run db:generate
npm run db:migrate
npm run db:seed
npm run dev
```

Open http://localhost:3000. Development credentials are `admin@example.com` / `ChangeMe123!` (change them immediately outside local development).

Windows PowerShell uses `Copy-Item .env.example .env`; Android testing uses the host machine's LAN IP, for example `http://192.168.1.10:3000`, while the dev server is started with `npm run dev -- --hostname 0.0.0.0`.

## Commands

- `npm run dev` — Next.js development server
- `npm run build && npm start` — production build/server
- `npm run lint` — ESLint
- `npm run typecheck` — TypeScript
- `npm test` — unit tests
- `npm run test:e2e` — Playwright simulator flow (requires dev server)
- `npm run db:up` / `npm run db:down` — local PostgreSQL
- `npm run db:migrate` / `npm run db:seed` — schema and demo data
- `npm run setup` — validates prerequisites, creates `.env` without overwriting it, and runs database setup

## Architecture

The Next.js App Router provides the UI and REST endpoints. Prisma owns the PostgreSQL schema. `src/lib/messaging` contains the provider contract and simulator adapter; webhook processing is idempotent on `(provider, providerMessageId)`. The fixed reply is generated by `src/lib/ai` so classification, priority, and suggested replies can be added without changing message processing.

Official messaging APIs only: no WhatsApp Web automation, scraping, QR session reuse, or reverse-engineered endpoints. Configure an approved business provider only after confirming its account type and terms. See `docs/providers.md` and `docs/api.md`.

## Security and deployment

Secrets belong in environment variables, not source control. Production must use HTTPS, a managed PostgreSQL instance, a strong `SESSION_SECRET`, a real mail/push notification strategy, provider webhook signature verification, backups, and a reverse proxy. `docs/security.md`, `docs/deployment.md`, and `docs/troubleshooting.md` cover the operational checklist.
